## Leon.C｜LazyGenius.dev

技術は目的ではなく、課題を解決するための手段です。

Webサイト制作、業務改善ツール、ブラウザ自動化、Webデータ収集、運用・デプロイまで、
「何を作るか」ではなく、**何を実現したいのか / 誰の手間を減らすのか / どう運用されるのか** から逆算して設計・実装しています。

WordPress、Laravel、Next.js、TypeScript、Astro、Cloudflare、Playwright などを使い、
必要十分な構成で、変更に強く、後から理解しやすい仕組みを作ることを重視しています。

**何を作ればいいか分からない段階から、現状を整理し、必要な一手を一緒に考える。**  
サイト制作だけでなく、既存システムの改修、データの扱い、サーバー・DBの運用まで、課題に応じて技術の境界を越えて取り組みます。必要なら作らない判断や、専門家・サービス提供元に任せる判断も含めます。

---

### Strength

- **課題から逆算する設計**：現状と達成条件を把握し、既存の仕組みを活かす・部分改修する・新しく作る・作らない選択肢から手段を選びます。
- **小さく作って、確実に進める**：まず全体像を掴み、1機能ずつ実装・検証しながら進めます。
- **保守しやすい実装**：責務分離、命名、コメント、README、設定の分離を重視し、後から見ても理解しやすい構造を目指します。
- **自動化・効率化**：人間が繰り返している作業や、散らばった情報の収集・整形・確認を自動化します。
- **作って終わりにしない**：デプロイ、動作確認、更新・保守の担当範囲、復旧方法まで考え、現実で使える形に落とし込みます。
- **予算と残余リスクを考える**：費用・納期・日々の運用負担を見比べ、必要な安全性を確保できる範囲で提案します。対策しないリスクや未検証事項も明確にします。
- **原因と責任範囲を切り分ける**：ログや実行環境を調べ、アプリ・DB・ホスティング事業者など、それぞれが担う範囲を整理してから対応します。

### Development Style

- 全体像を把握してから、1機能ずつ縦切りで実装・検証
- 型を「完成成果物の契約」として扱う設計
- 司令塔と実働処理を分けた責務分離
- 推測ではなく、ログ・Network・実データ・実行結果から判断
- 外部サービスは疎通確認から始め、read → write の順で安全に進める
- PHPUnit / Playwright / Node test などによる品質確認・自動テスト
- README・設計意図・技術選定理由をコード外にも残す
